# 相机–相机（Cam-Cam）手动 6-DOF 微调说明

本文说明在 `./calib_unified_run.sh --run --task cam-cam --manual`（或 `unicalib_cam_cam --config ... --manual`）进入 **OpenCV 双目对极线窗口** 后，如何用键盘微调 6 个外参、画面上会看到什么变化、以及推荐的调整思路。

更通用的按键与流程见 [MANUAL_EXTRINSIC_ADJUSTMENT.md](MANUAL_EXTRINSIC_ADJUSTMENT.md)。

---

## 1. 如何进入手动微调

1. 先完成编译：`./calib_unified_run.sh`（或 `--build-only`）。
2. 运行（示例）：
   ```bash
   ./calib_unified_run.sh --run --task cam-cam --manual
   ```
3. 前置条件：精标定已成功，且 Pipeline 已缓存 **左右相机各第 0 帧** 与内参；否则会提示无缓存并无法打开有效微调界面。
4. 需要图形环境（`DISPLAY` / X11 转发等），与 LiDAR-Cam 手动模式相同。

---

## 2. 窗口里显示什么？

实现见 `manual_calib.cpp` 中 `run_6dof_interactive_loop_cam_cam` 与 `render_stereo_epipolar_impl`。

| 内容 | 含义 |
|------|------|
| **左右水平拼接** | 左侧为 **参考相机（ref / cam0）** 图像，右侧为 **目标相机（target / cam1）** 图像。顺序与配置里 `cam_cam.pairs`（或 `camera_align`）一致：`[ref_id, target_id]`。 |
| **彩虹水平参考线** | **屏幕坐标**下每隔 **80px** 一条**水平**线。仅为行向辅助，**一般不与对极线垂直**（勿与极点同心圆混淆）。 |
| **对极线垂直参考线（圆/平行线）** | 这里的「垂直」分为两种几何情况：<br/>1. **有限极点**：绘制以极点为圆心的同心圆。圆在交点处的切线与对极线（半径方向）**严格正交**。<br/>2. **无穷远极点**（平行双目）：程序自动计算对极线束的平均方向，并画出一组与其方向向量 **(b, -a)** 垂直的平行线。无论外参如何旋转导致对极线倾斜，这组参考线始终与之**保持 90° 交角**。每条线颜色不同（HSV 彩虹），便于沿极线精确对齐对应点。 |
| **对极线** | 仍为 **80px** 网格采样：右图 **绿色**、左图 **橙色系**，由当前 **F** 计算。绘制在垂直参考线 **之上**。 |
| **绿色文字叠加** | 当前 **T (m)**、**RPY (deg)**、简要图例及按键提示。 |

几何关系采用经典双视图理论（与 *Multiple View Geometry* 中基础矩阵表述一致）：**F** 满足 **x₁ᵀ F x₀ = 0**。**极点–极线**：所有对极线过极点；以极点为圆心的圆与极线在交点处 **正交**（切线 ⊥ 极线）。**平行/近似平行双目**时极点常在 **无穷远**（e₃≈0），程序 **不绘制** 同心圆，仅保留彩虹横线与对极线；此时对极线常近似平行。

**注意**：已不再绘制屏幕固定竖线（易与对极几何混淆）。**是否标定正确**仍须看 **绿/橙对极线** 是否穿过真实同名点。

## 3. 外参在程序里的语义（读数与按键在改什么）

当前存储为 **`ExtrinsicSE3`：T_target_in_ref**，即 **把点从 target（右图相机）坐标系变到 ref（左图相机）坐标系**：

\[
\mathbf{p}_{\mathrm{ref}} = R\,\mathbf{p}_{\mathrm{target}} + \mathbf{t}
\]

- **R, t** 来自自动标定结果，作为初值。
- **旋转增量**：实现为 **右乘** 在 **target 相机系** 下的微小旋转后再合成到当前位姿（`T_new = T_old * δT`，δT 只有旋转）。因此同一按键在不同姿态下，对图像的“直观效果”会随当前姿态略有耦合，这是正常现象。
- **平移增量**：直接加减 **`POS_TargetInRef` 的 x/y/z 分量**（在 **ref 坐标系** 下改变平移部分，见 `apply_delta_translation`）。

调参目标：**在真实场景下，左右同名点与对极线一致**——即你肉眼认定的对应关系应落在当前 F 所决定的对极线上。

---

## 4. 六个参数分别是什么？图上会有什么反应？怎么调？

下列描述在 **典型车前向/水平双目、光轴大致平行** 时最直观；安装角较大时，可把“水平/竖直”理解为 **相机坐标轴相对场景** 的效果，原则仍是 **让对极几何与真实对应点一致**。

### 4.1 旋转（Q/A、W/S、E/D）

| 按键 | 参数 | 几何含义（直观） | 图上常见表现（对极线/结构） | 调整建议 |
|------|------|------------------|-----------------------------|----------|
| **Q / A** | Roll ± | 绕 **target 相机 X 轴**（右目系）的相对转动 | 两图相对“扭转”，对极线整体倾斜或交叉模式变化；竖直线在左右图中的相对倾角变化 | 先看明显横向结构（地平线、栏杆）：若左右“拧”了，先小步调 Roll |
| **W / S** | Pitch ± | 绕 **target Y 轴** | 对极线簇的 **竖直/水平走向** 与 **疏密** 明显变化；常表现为“上下视差”与线方向联动 | 有清晰地平线或路面消失点时，Pitch 不对往往表现为对极线与场景透视不一致 |
| **E / D** | Yaw ± | 绕 **target Z 轴** | 左右相机 **光轴不平行** 的主要分量；对极线是否像“从一点扇出”、左右视差方向是否沿期望方向 | 水平双目先 **小步扫 Yaw**，观察绿/橙线网是否与远处竖直线、车道线等结构相容 |

**原则**：旋转错时，往往 **整条对极线族** 与场景“拧在一起”；先把线族调到与明显 3D 直线、平面交界大致一致，再细调。

### 4.2 平移（R/F、T/G、Y/H）

| 按键 | 参数 | 几何含义（直观） | 图上常见表现 | 调整建议 |
|------|------|------------------|--------------|----------|
| **R / F** | Tx ± | 在 **ref 系** 下改变 **t 的 x** | 改变 **基线长度在 ref X 上的投影**，影响 F 中“视差尺度”相关项；对极线分布整体伸缩/剪切 | 若感觉“远近视差比例”不对，可小步调 Tx |
| **T / G** | Ty ± | 改变 **t 的 y** | 类似 **竖直方向的基线分量**，常驱动对极线 **整体上下倾斜或偏移模式** | 左右相机 **一高一低** 装错时，Ty 往往敏感 |
| **Y / H** | Tz ± | 改变 **t 的 z** | 改变 **前后相对**（沿 ref 深度方向的分量），对极线 **汇聚/发散** 形态、与无穷远点的关系 | 两目 **前后错位** 或共面误差大时，可试小步 Tz |

**原则**：平移 **整体改变 F**，不像单像素平移那样“只动一条线”；通常 **旋转先粗对齐结构，平移再补尺度与汇聚**。

## 5. 推荐操作流程（实操顺序）

1. **在左图选一个容易辨认的特征**（角点、灯、标志边缘），在右图找 **你认为的同名点**。
2. 观察：**右图上过该同名点的绿线**是否就是左图采样网格给出的那条线（ mentally：左图对应网格区域 → 右图一条绿线）。若系统偏差很大，先 **小步 E/D（Yaw）** 与 **W/S（Pitch）**。
3. 若整体有 **“旋转错位”感**，用 **Q/A（Roll）** 小步修正。
4. 当线族方向大致合理但 **尺度/汇聚** 仍别扭，再 **小步 R/F、T/G、Y/H**。
5. 多换几个距离层上的点（近、中、远）重复目测；**远近都一致** 时外参更可靠。
6. 满意后 **Enter 接受**；**Esc 放弃** 并保留自动标定结果。
7. 误操作多用 **U 撤销**。

---

## 6. 按键一览（Cam-Cam OpenCV 窗口）

| 按键 | 作用 |
|------|------|
| Q / A | Roll + / − |
| W / S | Pitch + / − |
| E / D | Yaw + / − |
| R / F | Tx + / − |
| T / G | Ty + / − |
| Y / H | Tz + / − |
| U | 撤销一步 |
| Enter | 接受当前外参并关闭窗口 |
| Esc | 取消手动微调 |

**默认步长**（`ManualAdjustStep`）：旋转约 **0.1°**，平移约 **0.005 m (5 mm)** 每次。

**说明**：LiDAR-Cam 部分路径支持 **Shift + 键** 放大步长；**当前 Cam-Cam 的 OpenCV 交互循环仅调用普通步长**（未传入 fast 模式）。若需更大步长，须改代码或后续在配置中暴露 `ManualExtrinsicAdjuster::Config::step`。

---

## 7. 判据小结

| 观察对象 | 好的状态 |
|----------|----------|
| 对极线族与 F | 真实同名点落在 **应有的** 对极线上 |
| 远近一致性 | 近景、远景特征同时满足上述关系 |
| 叠加读数 | T、RPY 连续变化无跳变；与车辆几何量级合理（平移米级、小角度为主） |

## 9. 与「点击精化」的关系

带 `--manual` 时，Pipeline 进入的是 **6-DOF 键盘 + 对极线可视化** 阶段。文档中提到的 **ManualClickRefiner::refine_cam_cam**（在图上点对应点再做优化）属于 **另一层 click-calib 精化**；若你当前可执行文件流程中未弹出点选界面，以实际终端说明为准，本文仅覆盖 **6-DOF 窗口** 行为。
