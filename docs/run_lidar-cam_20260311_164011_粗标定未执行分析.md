```

              └─ 建议: 在 config 中指定实际入口脚本（见下）
```

## 3. 可行修复方案

### 方案 A：在配置中指定 MIAS-LCEC 实际入口（推荐）

在 `unicalib_example.yaml`（或当前使用的配置）中增加：

```yaml
third_party:
  mias_lcec:
    # 仓库内无 src/calib_main.py，需指定实际入口（若 MIAS 提供命令行接口）
    calib_script: "bin/python/c3m.py"   # 或 mias_lcec.sh 对应的实际可执行脚本
```

**注意**：当前 MIAS-LCEC 工具箱可能是 GUI 或非 `--pcd/--image` 命令行接口；若没有现成命令行入口，需要写一层薄封装脚本，接受 `--pcd`、`--image`、`--sensor_config`、`--output_dir` 并调用现有工具，再把 `calib_script` 指到该脚本。

### 方案 B：在 MIAS-LCEC 仓库中提供适配器期望的脚本

在 `MIAS-LCEC/src/calib_main.py` 增加一个脚本，内部调用现有 `bin/python/c3m.py` 或其它实现，并接受与 UniCalib 适配器一致的命令行参数（如 `--pcd`、`--image`、`--sensor_config`、`--output_dir`）。这样无需改配置即可通过「脚本存在」检查并执行粗标定。

### 方案 C：仅验证「从数据源取首帧」逻辑（不跑 MIAS）

若暂时不修复 MIAS 入口，可修改代码：在 **MIAS 不可用时仍尝试从 ROS2/文件取首帧并写入 `coarse_input/`**，仅不调用 MIAS。这样可验证首帧提取与路径逻辑，粗标定仍不会执行，但日志中会出现「从 ROS2 取首帧」等记录。
